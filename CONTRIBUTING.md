# Contributing

Gracias por el interés. Este es un proyecto personal con un solo mantenedor.

1. Abre un issue antes de un cambio grande para acordar el alcance.
2. Haz un fork y una rama; los cambios entran por pull request, nunca directo a `main`.
3. Firma tus commits (`git commit -S`); la rama `main` exige commits verificados.
4. Corre `python3 .github/scripts/check_site.py` antes de abrir el PR.
5. Un PR, un propósito. Describe qué cambia y cómo lo probaste.

Vulnerabilidades: no uses issues, sigue [SECURITY.md](SECURITY.md).
